# 云相册 App 后端开发计划

> 版本：v1.0  
> 依据文档：`requirement-document.md`、`cloud-album-database-schema.sql`、`backend-technology-stack.md`  
> 适用项目：`spring-boot-cloud-prototype-app`  
> 编写目的：作为后续后端分阶段开发、评审、测试和验收的执行基线。

---

## 一、项目目标

建设云相册 App 后端服务，为联网云端相机和用户端 H5/App 提供完整的：

- 用户注册、登录、JWT 鉴权和密码重置
- 用户语言偏好及时区管理
- 云端相机永久绑定
- 设备身份认证和照片上传会话
- OSS 原图直传、上传回调和图片派生处理
- 相册查询、详情、原图下载和永久删除
- 存储容量、独立存储权益和到期自动清理
- 存储套餐、订单和乒乓支付回调预留
- 多语言业务通知
- 统一异常、限流、日志、幂等和安全控制

本计划遵循前后端分层原则：Controller 只处理 HTTP 接口，业务逻辑放在 Service/ServiceImpl，数据库访问通过 Mapper 和 XML 完成。

## 二、已确认的技术与架构约束

### 2.1 技术栈

| 分类 | 技术 | 用途 |
|---|---|---|
| 语言 | Java 21 | 后端开发和运行环境 |
| 构建 | Maven | 依赖管理、编译、测试和打包 |
| Web | Spring Boot 3.4.12、Spring Web | REST API |
| 校验 | Jakarta Validation | DTO 参数校验 |
| ORM | MyBatis-Plus 3.5.17 | Entity 映射和基础 CRUD |
| 数据库 | MySQL 8.0+ | 持久化业务数据 |
| 缓存 | Redis / Spring Data Redis | 验证码、限流、临时状态和缓存 |
| 连接池 | Druid 1.1.16 | 数据库连接管理 |
| 对象存储 | 阿里云 OSS SDK 3.18.5 | 原图、缩略图、预览图存储 |
| 安全 | Hutool JWT、Argon2id | JWT 和密码哈希 |
| 测试 | JUnit 5、Mockito、Spring Boot Test、MockMvc | 单元测试和接口测试 |

### 2.2 接口规范

- 对外接口只使用 GET 和 POST。
- Controller 只接收请求、读取认证上下文并调用 Service。
- Controller 不进行 DTO、Entity、VO 转换，不编写业务逻辑。
- POST 请求对象放在 `pojo/dto`。
- 数据库映射对象放在 `pojo/entity`。
- 前端返回对象放在 `pojo/vo`。
- 接口统一返回 `CommonResult<T>`。
- 成功响应统一使用 `CommonResult.success(...)`。
- Mapping 路径与方法名保持一致。
- 用户 ID 不允许由前端请求参数决定，必须从已验证 JWT 上下文读取。
- 设备上传不使用用户 JWT，使用设备 ID 和设备密码鉴权。
- 每新增或修改一个 Controller，同步维护对应 Postman Collection。

### 2.3 时间、金额和容量

- 数据库 `datetime(3)` 统一保存 UTC。
- 用户时区使用 IANA 标识，例如 `Asia/Shanghai`、`Europe/Berlin`。
- 用户自然日、自然月、自然年先按用户时区计算，再转换为 UTC 查询或保存。
- 时间区间统一采用左闭右开：`[startUtc, endUtc)`。
- 金额使用整数分保存，禁止使用浮点数。
- 文件大小和容量统一使用字节保存。

### 2.4 数据库约束

- 表之间不依赖外键约束，关联完整性由应用层维护。
- 所有状态字段使用枚举约束和 Service 状态机校验。
- 用户邮箱、设备业务 ID、订单号、权益编号、通知编号等业务唯一字段必须建立唯一索引。
- 密码、设备密码、JWT、OSS 凭证、支付密钥和数据库密码不得以明文写入源码、日志或文档。

## 三、数据库与领域模型

### 3.1 用户与认证领域

涉及表：

- `t_user`
- `t_email_verification_code`
- `t_notification`

需要实现：

1. 邮箱唯一性和规范化：去除首尾空格并转为小写。
2. 用户密码使用 Argon2id 哈希保存。
3. 注册验证码记录用途、状态、发送次数、失败次数、过期时间和请求 IP。
4. 验证码状态必须支持待验证、已验证、过期、作废和发送失败。
5. 注册和重置密码的验证码必须一次性消费。
6. 用户保存 IANA 时区和语言偏好。
7. 通知记录支持幂等键、语言、渠道、重试次数和发送状态。

### 3.2 设备领域

涉及表：

- `t_device`
- `t_device_binding`

核心规则：

- 一个用户最多绑定一个设备。
- 一个设备最多绑定一个用户。
- 绑定后永久强绑定，不支持解绑和换绑。
- 设备初始密码保存安全哈希。
- 设备状态必须区分未绑定、已绑定和已禁用。
- 所有设备上传归属只能从设备绑定关系推导，不能相信请求参数中的用户 ID。

### 3.3 存储权益领域

涉及表：

- `t_platform_config`
- `t_storage_plan`
- `t_user_storage_account`
- `t_storage_entitlement`

核心规则：

- 设备绑定成功后创建独立的设备赠送权益。
- 用户购买套餐时创建独立的购买权益。
- 多个未过期权益容量相加，不覆盖旧权益。
- 当前有效容量为所有有效权益容量总和。
- `used_bytes` 只计算已发布原图容量。
- `reserved_bytes` 记录上传过程中预留的容量。
- 权益到期后重新计算有效容量，必要时按上传时间从早到晚清理完整照片文件组。

### 3.4 上传与相册领域

涉及表：

- `t_upload_session`
- `t_photo`
- `t_photo_file`

上传会话状态建议保持：

```text
URL_ISSUED
→ ORIGINAL_UPLOADED
→ PROCESSING
→ COMPLETED
→ AVAILABLE
```

异常状态：

```text
EXPIRED
FAILED
DELETE_PENDING
DELETE_FAILED
```

只有原图、缩略图和预览图均上传成功，并且对应文件记录写入数据库后，照片才能进入 `AVAILABLE` 并被 H5 查询。

## 四、分阶段开发计划

## 阶段 0：项目基线和开发环境

### 目标

建立可重复编译、测试和运行的后端项目基线。

### 开发内容

1. 确认 Java、Maven、MySQL、Redis 和 OSS SDK 版本。
2. 创建 Spring Boot 主启动类和基础配置。
3. 配置开发、测试和本地环境 profile。
4. 配置 MySQL 连接池、MyBatis-Plus、Redis 和统一 UTC 时区。
5. 配置日志格式和敏感信息脱敏规则。
6. 执行数据库建表脚本并确认字符集、排序规则和索引。
7. 建立统一 `CommonResult<T>`、错误码和全局异常处理框架。
8. 建立基础测试目录和 Maven 测试命令。

### 验收标准

- `mvnw.cmd test` 能执行。
- 应用能够正常启动。
- MySQL、Redis 连接失败时有明确错误。
- 配置文件中不包含真实凭证。
- 数据库脚本可重复执行且不会破坏已有数据。

## 阶段 1：基础实体、枚举和数据访问层

### 目标

建立数据库表对应的 Java 数据模型和 Mapper XML。

### 开发内容

1. 为每张表创建 Entity。
2. 继承公共审计字段基类。
3. 使用 MyBatis-Plus 注解映射表名和字段。
4. 为 Entity 字段补充中文单行字段注释。
5. 创建状态、用途、来源、渠道和时间单位枚举。
6. 创建 DTO 和 VO 的基础目录结构。
7. 创建 Mapper 接口。
8. 将 SQL 全部放入 `src/main/resources/mapper/*.xml`。
9. 建立 resultMap、字段列表和状态更新 SQL。
10. 编写 Mapper 契约测试，检查 XML namespace、方法和 SQL 映射。

### 验收标准

- 所有数据库表有对应 Entity。
- Mapper Java 文件不写 SQL 注解。
- XML namespace 与 Mapper 全限定名一致。
- 基础查询、条件更新和锁定查询有测试。
- 字段类型、枚举值、时间和容量类型与数据库一致。

## 阶段 2：统一异常、参数校验和审计字段

### 目标

建立所有业务共用的错误、校验和审计机制。

### 开发内容

1. 定义错误码枚举。
2. 实现业务异常、认证异常、参数异常和外部服务异常。
3. 实现全局异常处理器。
4. 将参数校验错误统一转换为 `CommonResult`。
5. 实现 MyBatis-Plus 审计字段自动填充。
6. 未登录公开接口写入审计字段时不得抛出“请先登录”。
7. 统一日志级别，禁止打印密码、验证码、JWT 和 OSS 签名。

### 验收标准

- 参数错误、业务错误、未登录和系统异常返回不同错误码。
- 审计字段在登录和未登录场景均可正常填充。
- 全局异常不泄漏堆栈、密码、令牌或密钥。
- 异常处理有单元测试和 MockMvc 测试。

## 阶段 3：用户注册、验证码和密码安全

### 目标

完成注册、验证码验证、登录和忘记密码流程。

### 开发内容

#### 3.1 注册验证码

1. 校验邮箱格式和邮箱未注册。
2. 生成六位验证码。
3. 数据库存储验证码哈希，不保存明文验证码。
4. Redis 保存验证码临时状态。
5. 设置验证码 5 分钟有效期。
6. 设置同一邮箱 60 秒发送间隔。
7. 设置验证码失败次数上限。
8. 保存请求 IP 和发送审计信息。
9. 发送实现先提供 NoOp 适配器，正式邮件服务通过接口替换。

#### 3.2 注册

1. 校验邮箱、验证码、密码和确认密码。
2. 校验 `X-Time-Zone` 是否为有效 IANA 时区。
3. 读取并校验 `Accept-Language`。
4. 原子消费已验证验证码。
5. 创建 ACTIVE 用户。
6. 创建用户存储账户。
7. 返回注册结果，不返回密码或密码哈希。

#### 3.3 登录和 JWT

1. 按规范化邮箱查询用户。
2. 使用 Argon2id 比较密码。
3. 校验账号状态。
4. 签发包含用户 ID、时区、签发时间和过期时间的 JWT。
5. 后续请求从 JWT 上下文取得用户身份。
6. JWT 无效或过期时清理上下文并返回统一错误。

#### 3.4 忘记密码

1. 校验已注册邮箱。
2. 发送重置密码验证码。
3. 校验验证码并限制尝试次数。
4. 一次性消费验证码。
5. 更新密码哈希和密码更新时间。

### 主要接口

```text
POST /api/auth/sendRegisterCode
POST /api/auth/verifyRegisterCode
POST /api/auth/register
POST /api/auth/login
POST /api/auth/sendResetPasswordCode
POST /api/auth/verifyResetPasswordCode
POST /api/auth/resetPassword
POST /api/auth/logout
```

### 验收标准

- 注册验证码频控、过期、错误次数和重复消费均有测试。
- 缺少或错误时区不能注册。
- 登录成功返回 JWT，密码不出现在响应和日志中。
- 未登录访问受保护接口返回统一认证错误。
- 重置密码后旧密码不可登录，新密码可以登录。

## 阶段 4：JWT 拦截器、用户上下文和限流

### 目标

为受保护接口提供稳定的认证上下文和基础限流能力。

### 开发内容

1. 实现 JWT 解析和签名校验。
2. 实现请求级 `UserContextHolder`。
3. 请求完成后清理 ThreadLocal。
4. 区分公开接口、用户接口和设备接口。
5. 实现 IP、邮箱、设备 ID 等维度的限流。
6. 单机环境支持内存限流，生产环境支持 Redis 限流。
7. 限流异常返回统一错误码。

### 验收标准

- 请求之间不会串用用户上下文。
- 并发限流测试达到配置上限。
- JWT 过期、签名错误、格式错误分别可识别。
- 公开认证接口不被用户 JWT 强制拦截。

## 阶段 5：用户资料、语言和时区

### 目标

实现用户资料读取、语言同步和时间规则的统一入口。

### 开发内容

1. 实现用户资料查询。
2. 实现语言偏好更新。
3. 从 JWT 读取用户 ID 和用户时区。
4. 统一 UTC 时间工具和用户本地日期范围转换。
5. 实现自然月、自然年到期时间计算。
6. 处理夏令时和月末日期不存在的情况。
7. 实现中文、英语、德语错误码映射预留。

### 主要接口

```text
GET  /api/user/getProfile
POST /api/user/updateLanguage
```

### 验收标准

- 用户不能通过请求参数读取其他用户资料。
- 日期查询使用用户时区转换后的 UTC 边界。
- 月末和夏令时测试通过。
- 语言代码不支持时回退英语。

## 阶段 6：设备维护和永久绑定

### 目标

完成设备数据库维护约定和用户永久绑定流程。

### 开发内容

1. 编写设备初始化 SQL 脚本。
2. 设备 ID 建立唯一约束。
3. 初始密码使用 Argon2id 哈希。
4. 校验设备 ID 格式。
5. 校验设备存在、启用状态和初始密码。
6. 锁定用户和设备记录，避免并发重复绑定。
7. 校验用户是否已有设备。
8. 校验设备是否已经被绑定。
9. 创建永久绑定记录。
10. 原子更新设备状态。
11. 创建设备赠送存储权益。
12. 创建用户存储账户。

### 主要接口

```text
GET  /api/device/getMyDevice
POST /api/device/bindDevice
```

### 验收标准

- 用户只能绑定一个设备。
- 设备只能绑定一个用户。
- 并发绑定只能成功一次。
- 绑定成功后生成赠送权益。
- 设备密码和密码哈希不出现在 VO、日志和错误响应。
- 设备绑定失败事务整体回滚。

## 阶段 7：设备上传会话和容量预留

### 目标

实现仅允许已绑定设备申请上传链接的上传会话流程。

### 开发内容

1. 设备 ID + 设备密码鉴权。
2. 校验设备为已绑定状态。
3. 从绑定关系取得用户 ID，禁止请求传入用户 ID。
4. 校验文件扩展名、MIME 类型和文件大小。
5. 查询用户有效容量。
6. 计算已使用容量、预留容量和本次文件大小。
7. 容量足够时原子增加预留容量。
8. 创建上传会话和对象存储路径。
9. 生成短时有效 PUT 预签名 URL。
10. 返回上传 URL、HTTP 方法、必须携带的请求头和过期时间。
11. 实现上传会话状态查询。
12. 定时释放过期上传会话的预留容量。

### 主要接口

```text
POST /api/deviceUpload/createUploadSession
POST /api/deviceUpload/getUploadSessionStatus
```

### 验收标准

- 用户 JWT 不能申请设备上传 URL。
- 未绑定设备不能申请 URL。
- URL 只能 PUT 到服务端生成的对象路径。
- URL 过期后不可使用。
- Content-Type 必须与签名值一致。
- 容量预留和释放具备并发安全性。
- 上传会话失败不会永久占用容量。

---

## 阶段 8：OSS 回调、图片处理和照片发布

### 目标

实现原图上传完成后的安全回调、派生图生成和照片发布。

### 开发内容

1. 在预签名 URL 中绑定 OSS callback 和 callback-var。
2. 回调携带上传会话编号、对象键、大小、MIME 类型、事件 ID 和回调时间。
3. 校验 OSS 回调签名。
4. 校验上传会话存在、状态和对象键。
5. 通过 OSS HeadObject 获取实际元数据。
6. 比较实际对象大小、Content-Type、对象键和会话声明。
7. 原子更新上传会话为原图已上传或处理中。
8. 下载原图并生成缩略图和预览图。
9. 派生图长边限制：缩略图约 480px，预览图约 1920px。
10. 上传派生图并校验其元数据。
11. 创建原图、缩略图和预览图文件记录。
12. 只有完整文件组成功后才创建可访问照片记录。
13. 失败时清理对象、释放资源并记录可重试状态。
14. 回调必须幂等，重复事件不能重复扣容量或重复发布照片。

### 主要接口

```text
POST /api/ossCallback/uploadCompleted
```

### 验收标准

- 无效回调签名被拒绝。
- 对象键不匹配被拒绝。
- 文件大小或 MIME 类型不匹配被拒绝。
- 重复回调不会重复创建照片。
- 派生图失败不会产生可访问照片。
- 原图、缩略图、预览图必须作为完整文件组发布。
- 原图下载和回调均不泄漏 OSS 长期凭证。

### 正式上线前阻塞项

当前固定密钥回调校验器只能用于本地测试。正式接入阿里云 OSS 时，需要根据阿里云官方回调签名规则实现生产级验签，并确认回调 URL 可被 OSS 访问。

---

## 阶段 9：相册查询、详情、下载和删除

### 目标

实现 H5 相册的完整消费链路。

### 开发内容

1. 按用户 ID 查询 `AVAILABLE` 照片。
2. 支持今天、最近 7 天、最近 1 个月和全部筛选。
3. 将用户时区边界转换为 UTC 查询。
4. 使用游标分页，避免大页码性能问题。
5. 返回缩略图临时访问地址。
6. 查询照片详情并返回预览图地址。
7. 下载原图前校验照片归属和状态。
8. 生成短时原图下载 URL。
9. 支持最多 9 张照片批量删除。
10. 删除原图、缩略图、预览图和关联数据库记录。
11. 删除完成后扣减已用容量。
12. 删除失败进入可重试状态，不产生部分成功的错误展示。

### 主要接口

```text
GET  /api/photo/listPhotos
GET  /api/photo/getPhotoDetail
GET  /api/photo/getOriginalDownloadUrl
POST /api/photo/deletePhotos
```

### 验收标准

- 用户不能查询或删除其他用户照片。
- 日期筛选跨时区正确。
- 相册只展示 `AVAILABLE` 照片。
- 删除前后容量和照片列表一致。
- 下载 URL 短时有效且不能用于其他对象。
- 删除确认明确提示不可恢复。

---

## 阶段 10：存储概览、套餐和独立权益

### 目标

实现容量展示、套餐查询和权益叠加模型。

### 开发内容

1. 查询总容量、已使用容量、预留容量和剩余容量。
2. 查询用户全部有效权益明细。
3. 查询当前生效套餐。
4. 套餐按排序字段返回。
5. 购买权益按独立记录创建，不覆盖既有权益。
6. 权益有效期按用户时区计算后保存 UTC 到期时间。
7. 订单使用套餐快照，后续套餐变更不影响历史订单。
8. 容量不足时阻止上传会话创建。

### 主要接口

```text
GET /api/storage/getOverview
GET /api/storage/listEntitlements
GET /api/storagePlan/listActivePlans
```

### 验收标准

- 多个有效权益容量正确相加。
- 单个权益到期只减少该权益容量。
- 过期权益不参与容量计算。
- 套餐下架后不能创建新订单，但不影响历史权益。
- 容量单位始终为字节，展示转换在 VO 或前端完成。

---

## 阶段 11：权益到期自动清理和通知

### 目标

实现容量权益到期后的安全清理和用户通知。

### 开发内容

1. 定时扫描即将到期和已到期权益。
2. 使用分布式锁避免多实例重复清理。
3. 重新计算用户有效总容量。
4. 如果已用容量不超额，不删除照片。
5. 如果超额，按上传时间从早到晚删除完整文件组。
6. 每次删除同步扣减已用容量。
7. 删除原因写入照片文件状态。
8. 清理前、清理中、清理后发送多语言通知。
9. 通知失败支持重试和退避。
10. 清理过程具备幂等性和故障恢复能力。

### 验收标准

- 多实例同时执行时同一用户只清理一次。
- 删除顺序严格按照上传时间。
- 删除后容量不超过有效容量。
- 清理异常可重试，不重复扣减容量。
- 通知使用用户语言偏好。
- 所有删除操作明确不可恢复。

---

## 阶段 12：支付订单和乒乓支付回调

### 目标

完成支付订单创建、支付参数生成和异步回调处理的安全骨架。

### 开发内容

1. 校验套餐存在、状态有效和当前可售。
2. 读取当前登录用户 ID。
3. 使用客户端幂等号防止重复创建订单。
4. 保存套餐名称、容量、有效期、金额、币种和版本快照。
5. 生成乒乓支付参数或支付链接。
6. 不在后端源码或前端保存商户密钥。
7. 接收支付平台回调原文。
8. 校验回调签名。
9. 校验订单号、金额、币种、支付渠道和订单状态。
10. 保存回调审计记录。
11. 同一回调事件幂等处理。
12. 仅在异步回调验签成功后将订单标记为已支付。
13. 依据订单快照创建唯一存储权益。
14. 支付失败、金额不一致和重复回调不得开通权益。

### 主要接口

```text
POST /api/paymentOrder/createOrder
GET  /api/paymentOrder/getOrder
```

支付平台回调接口地址和字段必须以乒乓支付正式文档为准，未获得正式协议前不得猜测验签算法、字段名或回调状态。

### 验收标准

- 同一客户端幂等号只创建一个订单。
- 前端回跳不能直接开通权益。
- 回调重复到达不会重复创建权益。
- 金额、币种、订单号任一不一致都拒绝开通。
- 回调原文和验签结果可审计。

---

## 阶段 13：多语言通知

### 目标

完成验证码、权益、清理和支付结果通知的多语言模板能力。

### 开发内容

1. 定义通知类型、语言和渠道枚举。
2. 创建通知模板提供器。
3. 支持中文、英语和德语。
4. 模板变量统一命名和转义。
5. 敏感变量脱敏，不记录验证码、密码和令牌。
6. 实现邮件发送接口和本地 NoOp 实现。
7. 支持通知幂等、失败重试和状态更新。
8. 用户切换语言后同步影响后续服务端通知。

### 验收标准

- 所有用户可见业务通知都有三语言模板。
- 缺失语言回退英语。
- 模板变量正确替换。
- 敏感信息不会进入日志。
- 重复通知不会重复发送。

## 阶段 14：接口文档、Postman 和联调

### 目标

形成可供 H5 开发和测试使用的接口契约。

### 开发内容

1. 为每个 Controller 维护 Postman Collection。

### 验收标准

- 接口文档与 Controller、DTO、VO、错误码保持一致。

## 阶段 15：安全、并发和全链路验收

### 目标

在交付前验证安全性、数据一致性和故障恢复能力。

### 安全检查

- 密码只保存 Argon2id 哈希。
- JWT 密钥和 OSS 凭证来自环境变量。
- 日志不打印密码、验证码、JWT、签名 URL 和密钥。
- 用户 ID 不信任请求参数。
- 设备上传必须经过设备凭证和绑定关系校验。
- OSS URL 绑定对象键、Content-Type、回调和有效期。
- 回调校验签名、对象键、大小和 MIME 类型。
- 原图下载 URL 短时有效。
- 接口具备限流。

### 并发检查

- 并发设备绑定只能成功一次。
- 并发验证码发送受 Redis 限制。
- 并发上传预留不会超额。
- 并发删除不会重复扣容量。
- 并发支付回调不会重复开通权益。
- 定时清理任务具备分布式锁。

### 全链路验收

1. 注册并登录。
2. 获取 JWT 并读取用户资料。
3. 绑定设备并获得赠送权益。
4. 设备申请上传会话。
5. 使用 PUT 预签名 URL 上传原图。
6. OSS 自动回调后台。
7. 后台生成缩略图和预览图。
8. H5 查询相册和照片详情。
9. 下载原图。
10. 批量删除照片并更新容量。
11. 创建存储套餐订单。
12. 模拟支付回调并创建购买权益。
13. 权益到期后触发超额清理。
14. 检查通知、审计记录和异常恢复。

## 七、明确阻塞项和待确认事项

1. **乒乓支付正式协议**：缺少正式回调字段、签名算法、密钥配置和状态定义前，不实现供应商级验签。
2. **OSS 回调公网地址**：本地 `localhost` 或 `127.0.0.1` 无法被阿里云 OSS 访问，需要公网 HTTPS 域名或内网穿透。
3. **邮件服务**：NoOp 发送器只能用于开发测试，生产环境需要邮件供应商和模板配置。
4. **图片处理策略**：需要确认 ImageMagick、Java 图像库或独立图片处理服务；HEIC 解码能力需要单独验证。
5. **数据库安全策略**：数据库脚本维护设备、平台配置和套餐时，需要纳入发布审批和回滚流程。
6. **OSS 回调验签**：测试固定密钥不能直接用于生产，必须替换为正式回调验签实现。
7. **数据库设计差异**：需求文档中部分字段描述与实际实现可能存在差异，开发每阶段应以当前数据库脚本、实际 Entity 和已确认需求共同校对。

## 八、开发执行规则

后续按本计划开发时，每次用户指定阶段后：

1. 先读取该阶段涉及的 Controller、DTO、Entity、VO、Mapper、XML 和配置。
2. 检查 Git 工作区，区分已有修改和本阶段修改。
3. 先确认数据库字段、接口约定和现有代码实际状态。
4. 只实现当前阶段范围，避免无关重构。
5. 编写测试后再实现或同步补充回归测试。
6. 完成后运行编译、定向测试或全量测试。
7. 检查 `git diff --check` 和敏感信息。
8. 使用中文提交信息提交已完成阶段。
9. 报告已完成内容、验证结果和剩余阻塞项。
